# Milestone 2 — Resource Demand Prediction Engine

## Overview

Milestone 2 adds a regression-based resource demand prediction engine on top of the existing Milestone-1 disaster response backend. It uses **proxy-derived** historical targets (not observed resource consumption) and integrates with the existing grid analysis pipeline.

## Architecture

```
DisasterZone (M1) → grid geometry / severity / analyze_grid
        │
        ▼
  M2 feature assembly + district polygon intersection
        │
        ▼
  Ridge model (selected) + conformal 90% intervals
        │
        ▼
  FastAPI /prediction/* + prediction history (JSONL)
```

## Historical Data

- **33,032** normalized DESINVENTAR records (Odisha, Tamil Nadu, Uttarakhand)
- **80** target districts in `data/district_target_states.geojson`
- **73** districts with historical XML coverage; **7** newer TN districts without historical records
- **No observed** food/water/medical/shelter labels in XML
- `target_is_observed=false`, `target_method=impact_based_proxy_v1`

## Proxy Targets (B2 — approved, not modified)

Targets are generated by `impact_based_proxy_v1` (see `app/config/proxy_target_config.json`).

> Historical observed resource-demand labels were unavailable. Resource-demand targets are deterministic impact-based proxies constructed from available disaster-impact variables and are intended for prototype/model-comparison purposes.

## Model Training

### Algorithms compared

1. **Ridge Regression** — linear baseline (with scaling) — **selected for all 4 targets**
2. **Random Forest Regressor** — nonlinear ensemble
3. **XGBoost Regressor** — boosted trees

### Split strategy

Chronological split by `event_year` (train / validation / test). No random shuffling of temporal records.

### Selection criterion

Lowest **validation RMSE** per target.

### Train models

```bash
cd backend
python scripts/train_demand_models.py
```

Artifacts saved to `backend/models/`.

## Uncertainty

**Method:** Split conformal prediction intervals (90% nominal coverage) using absolute residuals on a calibration split.

- Exposed as `prediction_interval_lower` / `prediction_interval_upper`
- **Not** classical confidence intervals

## Vulnerability Weighting

Historical XML does **not** contain reliable elderly/children/medically-dependent demographics.

- Module: `app/services/prediction/vulnerability.py`
- Default: neutral factor `1.0` when data unavailable
- Accepts optional ratios when provided via API

## Grid / District Integration

- Polygon intersection in **EPSG:7755** (projected CRS for area-based overlap) for overlap areas
- One-to-many grid↔district relationships preserved
- Overlap proportions normalized to sum to 1.0

## Module-1 Integration Flow

```
DisasterZone (M1 DB record)
  → build_grid_geojson_from_zone()  [GRID_CELL_SIZE cell at centroid]
  → analyze_grid()                  [M1 population/buildings/severity]
  → enrich_grid_with_districts()    [polygon intersection]
  → recalculate_grid_demand()       [M2 model + intervals]
  → record_prediction()             [history JSONL]
```

M1 grid generation and severity logic are **not** replaced or duplicated.

| POST | `/prediction/scenario` | Scenario simulation |

## Dynamic Recalibration

- Field reports via `field_report_overrides` on grid/zone endpoints
- Satellite input: optional `satellite_placeholder` (status metadata only, no fabricated damage)
- Each prediction appends to `backend/datasets/prediction_history.jsonl`
- Model artifacts are **not** retrained on recalculation

## Limitations

1. Resource targets are **proxy-derived**, not observed ground truth
2. 2026 OSM/TIF are **current** spatial inputs, not historical labels
3. **Satellite** damage assessment is a placeholder
4. **NDMA** integration is a placeholder
5. Vulnerability demographics unavailable unless explicitly supplied
6. M1 zones store centroids only; grid cell rebuilt from `GRID_CELL_SIZE`
7. Zero-inflated impact data produces many zero proxy targets
